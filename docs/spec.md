# 動作仕様

[要件](requirements.md)に対応するMVP。

CLI（R-15）: elconv INPUT.mp4 [--output-dir DIR] [--language ja] [--whisper-model MODEL] [--article-model MODEL] [--no-article] [--overwrite]

出力先の既定は入力と同じフォルダ。日本語・空白入りパスを扱う。終了コードは成功0、入力・設定不備2、処理失敗1。既定は Whisper `small`（CPU/int8）、Gemini `gemini-3.5-flash-lite`。時刻境界で約12,000文字ごとに分割し、API一時障害は最大3回（待機1秒、2秒）再試行する。これらは実測前の暫定値で、`--help` とREADMEに示す。1件当たりの料金上限は未設定なので利用者がAPI利用前に料金とクォータを確認する。

正式名称・配布名は `elearning-converter`。`pip install -e .` で短縮コマンド `elconv` を登録する。代替起動は `python -m elearning_converter`。旧名称のコマンド・モジュールは提供せず、既存環境では旧配布パッケージをアンインストールしてから再インストールする。略称 `elconv` は e-learning converter に由来する採用値で、A-13により起動を検証する。

## 処理順

1. MP4、出力先、既存出力、通常モードのAPIキーを事前検査。キーは環境変数を優先し、未設定ならプロジェクトルートの `.env` を参照する。`--no-article` ではキーを読まない。
2. ffprobeで音声を確認し、FFmpegでモノラル16 kHz PCM WAVを一時生成。
3. 16 kHzモノラル16-bit PCM WAVをローカルで読み込み、faster-whisperへ配列として渡して開始・終了時刻とテキストを取得。空なら失敗。
4. [HH:MM:SS]付き原文Markdownを生成。
5. 通常モードでは時刻境界で分割し、APIで記事化・統合。--no-article は省略。
6. UTF-8の一時ファイルに書き最終名へ置換。一時WAVは必ず削除。

記事 <stem>.md は入力stemのタイトル、短い下書き注記、講義の流れに沿う本文を含む。固定の「要点」「本文」「用語」欄は作らず、用語を文脈で説明し、必要な前提・理由・具体例を残す。定型的な「講義では〜紹介された」などの前置きを省く。見出しと表は理解を助ける場合だけ使う。段落末・箇条書き末の句点などを省き、文同士の境界と意味の区切りに必要な句読点は残す。文字数の上限・短縮率は固定しない。句読点の機械的な一括削除は行わない。

API応答は body（heading, text, timestamp の配列）と checks（時刻を含む要確認事項の文字列配列）のJSON。bodyは1件以上、textはMarkdown本文で空不可、timestampは根拠の開始時刻。headingは空文字で見出しなしにできる。細かな段落ごとに見出しを要求しない。text内に見出しは書かずheadingへ分離する。通常段落は末尾に時刻を付け、表・箇条書き・コードブロックを含む場合は時刻を独立した段落にする。分割結果は順番にローカルで結合し、連続する同一見出しは1回だけ表示する。異なる見出しを挟んだ同名見出しは保持し、本文は削除しない。checksは完全一致の重複のみ省き、存在する場合だけ末尾の「原文で確認する箇所」にまとめる。追加の統合APIは呼ばない。

原文 <stem>.transcript.md は時刻付きセグメントを保持。フィラーや重複をノートから除き、不明瞭な語は時刻とともにchecksへ入れる。根拠のない補完をしない。

入力欠落、非MP4、音声なし、FFmpeg不在、認識空結果、APIキー欠落、API障害、出力不可は理由付き非ゼロ終了。APIの408、429、5xxと通信タイムアウト・接続障害だけを最大3回試行し、その他の400系は再試行しない。失敗時は数値HTTPステータス（取得できた場合）と例外クラス名のみ表示する。APIの生のエラー文やレスポンス内容は表示しない。既存出力は --overwrite なしでは変更しない。記事失敗時の原文救済名は `<stem>.transcript.failed.md` とし、作成できた場合は部分成功を明示する。救済ファイルも既存時は `--overwrite` が必要。不完全記事を最終名で残さない。

文字起こしの内部例外は「モデル読み込み」「音声読み込み」「推論・結果処理」の段階と例外クラス名を表示する。内部例外の本文、パス、キー、文字起こし本文は表示しない。

## 受入シナリオ

情報保持（R-18 / T-24）：各処理について、原文で明示される入力・初期値・比較条件・更新順序・停止条件・出力を本文に残す。具体例は全発話の再掲を要求しないが、変数更新・探索の成功と失敗・再帰の理解に必要な例を省かない。表や疑似コードは原文から確認できる範囲で使用し、不明箇所を埋めて実行可能に見せない。非手順型の講義へ固定の項目を強制しない。

不確かな認識語は本文の定義に使わず、確認できる説明と局所的な「名称／式／条件は要確認」を残す。checksには入力内の時刻、不確かな箇所、確認すべき内容を記す。原文内に矛盾があれば双方の時刻を示し、一般知識で一方を正解として確定しない。疑わしい一箇所のために説明全体を省略しない。

本文は実際の説明箇所ごとにbody要素を分け、根拠となる入力内の開始時刻を選ぶ。同一話題の続きはheadingを空にできる。目次の時刻や一つの時刻を無関係な複数の説明へ流用しない。分割で前後が欠ける場合は推測で接続せず、確認事項へ記す。応答直前に情報保持・概念の区別・不確実性・時刻を同じ生成内で点検する。追加API呼び出しは行わない。

## 既存原文入力（R-19 / A-20）

`elconv INPUT.transcript.md --from-transcript [--output-dir DIR] [--article-model MODEL] [--overwrite]`。`.transcript.failed.md`も受け付ける。対応接尾辞を除いた名前の`.md`のみ保存する。入力はUTF-8（BOM可）、elconvのタイトル・注記・空行と`[HH:MM:SS] 本文`行。時刻は分秒00～59、非減少（同時刻可）、本文は非空。未知の行・空結果・読取不能はAPI前に終了コード2で拒否。`--no-article`併用は拒否、認識言語・Whisperモデルは使用しない。出力は既定で入力と同じ場所、既存記事は--overwrite必須。入力と出力が同一実体の場合は上書き指定でも拒否。API失敗は終了1、救済原文の複製は不要。通常のMP4モードは維持する。

A-20：架空原文で正常・不正入力、BOM、日本語空白パス、同時刻、逆順、既存出力、API失敗を検証し、音声処理未呼出し・入力不変・記事のみ保存を確認する。実APIは別途承認後に評価する。

## 品質確認（R-20 / A-21）
--quality-checkはMP4と--from-transcript双方で利用でき、--no-articleとは併用不可。以下は通常モードの追加APIなし・原文のみ送信という仕様の明示的な例外。
生成応答はarticle(body/checks)とfacts（時刻・重要事項）のJSON、照合応答はissues（severity=major/minor、時刻、説明）のJSON。issuesの有無で修正を最大1回行い、再照合する。最終majorがあれば全記事を保存せず終了1。適切な留保はmajorにしない。minorはレポートに残し記事を保存する。形式不正は修正依頼で救済せず即失敗。各呼出しの通信再試行は最大3試行、実試行数も記録する。
品質モードの分割は約12000文字以内、末尾20%に開始時刻間隔5秒以上の境界があれば最も後ろの境界を優先。前後各2セグメント（各600文字まで）を参照専用として送る。値は暫定で、実生成時に欠落・重複を評価する。同一時刻が境界にまたがる場合は時刻だけでは識別不能なため文脈の指示と照合に依存する。
<stem>.quality.mdにモデル、工程回数、再試行を含むAPI試行数、分割ごとの初回/再照合指摘・未解決事項・記事保存状態を記す。生応答・キーは保存しない。レポートも--overwrite必須、入力/他出力との同一実体は拒否。API前に衝突を検査。レポート保存後に記事を確定し、保存失敗は終了1（レポートには記事の保存未確認と記す）。既存記事は品質不合格・API失敗では変更しない。MP4モードは従来の原文救済を維持。
A-21：モックで2/4回、重大問題残存、軽微事項、生成/照合の不正応答・打切り、通信再試行、後続分割失敗、レポート衝突、通常経路、入力保持を検証する。意味の検出は架空原文の欠落項目・添字上限と回数・条件・停止・不明式の断定を実API評価するための観点として定義し、モック結果を検出能力の実証としない。

## 台帳方式（R-21 / A-22）

以下の第1段階の仕様は、R-23〜25の完成方式で更新する。過去の4/6回は抽出窓内で完結した第1段階の値であり、完成方式の回数には使わない。
`--note-pipeline`はMP4/`--from-transcript`双方で使い、`--quality-check`/`--no-article`と併用不可。出力・衝突検査・上書き・原文救済は品質確認方式と共通。既存原文ファイルは変更しない。
原文順にS000001等のIDを付け、長い原文は文字範囲を持つS000001P0001等へ細分化。分割間・同時刻でも一意。約12000文字の本文対象と前後各2断片（本文各600文字まで）を送る。これは暫定的な文字数分割で、意味による分割と全体構成は後続タスク。
台帳はfacts（id、kind、text、source_ids、status）とexcluded（source_id、reason）。kindはdefinition/premise/reason/procedure/condition/example/exception/other、statusはconfirmed/uncertain。情報IDは分割内でF001等の一意なID。根拠は対象分割に限定し、各原文断片はfactsの根拠またはexcludedのどちらかに必須。フィラーや同じ説明の反復だけを除外し、重要な説明の除外は台帳照合で検査する。
台帳照合は原文からの欠落・除外理由・根拠・不確実性を検査。majorがあればその場で未合格終了（台帳は自動修正しない）。本文はheading/text/fact_ids/source_idsの配列とchecks。全factsに本文の対応が必須で、各本文のsource_idsはそのfact_idsの根拠集合と一致させる。時刻はモデルに作らせず根拠IDからローカルで導出。本文照合も元原文を参照し、IDを付けただけの意味的欠落・創作・不明語の断定を検査する。
本文照合に指摘がある場合だけ台帳を固定したまま本文を1回修正し再照合。通常4回、最大6回/分割。各呼出しは既存と同じ一時障害のみ最大3試行。形式不正は即失敗。レポートに原文IDと時刻・文字範囲、台帳内容・除外理由、本文番号と情報ID・根拠ID、照合履歴・呼出し数を保存する。生の応答と原文全文は保存せず、派生内容は教材と同じ管理を要する。

## 評価セット（R-22 / A-23）
`tests/fixtures/note_pipeline.json`の架空原文と人手の期待事項を使い、初期値・条件・更新順・停止・具体例・不明名称を評価する。正常応答の表示と、未掲載IDの拒否を自動検証する。意味を変えたままIDだけ残す劣化例は人手/実API照合用で、ローカル構造検査では検出できないことを明記する。比較手順は`docs/note-pipeline-evaluation.md`に記す。

## 完成台帳方式（R-23〜25 / A-24〜26）
抽出窓は約12000文字（本文とID用の概算）を上限とし、末尾20%内の話題転換語、文末、5秒以上の開始時刻間隔の順に境界を優先する。開始時刻間隔は無音の長さではない。手掛かりがなければ文字数上限で分割する。境界ヒューリスティックは意味解析の保証ではなく、全体計画で情報のまとまりを改めて決める。ID・文字範囲は分割前に付与する。参照用の前文脈は直前断片の末尾600文字、後文脈は直後断片の先頭600文字を使い、送信する範囲に文字オフセットを合わせる。
フィラーのみの窓は全原文IDにexcludedの理由があればfactsを空にできる。全窓でfactsが空なら、章計画を呼ばず記事化失敗とする。
すべての抽出窓で台帳抽出/照合後、分割番号を付けた情報ID（C0001.F001等）で全台帳を計画APIへ送る。plan.sectionsはheading/fact_ids。全情報を重複なく講義順に含むことをローカルで検査する。計画資料のJSONが120000文字を超える場合は送信せず失敗する暫定上限（暗黙に切り捨てない）。
章ごとに根拠原文を集め、本文対象の原文量が約12000文字以下になるよう情報単位で生成ジョブに分ける。章が長ければ複数ジョブとし見出しは最初だけ表示。前後の原文各2断片は参照専用。計画は文体補助であり本文の事実根拠には使わない。全情報が本文に1回以上対応すること、各ブロックの根拠が対応情報の根拠集合に一致することを検査する。
生成JSONはblocks/checks。ブロックはkind（paragraph/bullets/steps/table/code）、text/items/columns/rows/language、fact_ids/source_idsを持つ。未使用の欄は空文字/空配列とし、paragraph/codeはtext、bullets/stepsはitems、tableはcolumnsとrowsを使う。表の行は列数一致、codeのlanguageは英数字等の短い識別子。書式のMarkdownはローカル生成し、文字列をエスケープする。
各ジョブを生成/照合し、指摘時のみ台帳と計画を固定して1回修正/再照合する。最後に隣接するジョブの原文・本文を組にして、章境界の重複・概念混同・矛盾・説明の接続を別APIで照合する。境界照合は自動修正せずmajorで失敗。正常な長い説明の継続や原文の矛盾の適切な留保を誤指摘しないよう指示する。
抽出窓数W・生成ジョブ数Jでは通常2W+1+2J+max(J-1,0)回、修正時最大2W+1+4J+max(J-1,0)回。通常/既存品質方式は変更しない。`--max-api-calls N`は台帳方式専用の正整数、既定100。工程数が上限に達した場合は送信前に失敗（HTTP/通信の一時障害は各工程最大3試行）。工程上限はトークン量や料金の上限ではない。
レポートに計画とジョブの対応・抽出台帳・元ID/時刻/範囲・全照合履歴、工程上限、工程別試行数/秒数、取得できたprompt/candidates/thoughts/cachedトークン数と使用量取得不能回数を保存する。通信失敗試行の使用量は不明として区別し、合計が完全とは断定しない。CLIは固定の工程名と番号だけで進捗を表示し、原文/台帳/モデル出力をログへ出さない。
