# 文書案内

目的別に参照先をまとめる。ここには仕様や検証結果の本文を複製せず、それぞれの管理元へリンクする。

## 種類別の配置

```text
docs/
  requirements.md             要件・受入基準
  spec.md                     CLI・入出力・応答の仕様
  design.md                   モジュール構成・設計
  tasks.md                    実装・評価の進捗
  verification.md             日付付きの検証履歴
  user-material-test.md        実教材テストの手順
  note-pipeline-evaluation.md  品質比較の手順
  note-example.md             架空の出力見本
  note-fidelity-example.md     架空原文と情報保持の期待見本
  issues/
    known-issues.md            未解決問題・次の検証
  workflows/
    development-workflow.md    開発と引渡しの運用
  guides/
    documentation-map.md      この文書
```

新規の管理文書を`issues`・`workflows`・`guides`に分類した。既存文書はREADME、AGENTS.md、相互リンクやテストから参照されているため、今回の整理では配置を維持する。READMEは利用者の編集予定に従い変更していない。

## 目的から探す

| 知りたいこと | 参照先 | 管理する情報 |
| --- | --- | --- |
| 何を満たすべきか | [要件](../requirements.md) | R番号、受入基準、利用条件 |
| CLIや出力はどう動くか | [仕様](../spec.md) | オプション、応答構造、保存・失敗時の動作 |
| どう実装するか | [設計](../design.md) | モジュールの責任、検証・生成・保存の設計 |
| 何が終わり、何が残るか | [タスク](../tasks.md) | T番号、対応するR/A番号、作業の進捗 |
| どの条件で何を確認したか | [検証記録](../verification.md) | 日付、検証方法、結果、確認できない範囲 |
| 今どの問題を解決すべきか | [未解決問題](../issues/known-issues.md) | 問題の影響、事実と仮説、優先度、次の検証 |
| 開発・コミットをどう進めるか | [開発の進め方](../workflows/development-workflow.md) | 作業順、ブランチ、権限、データ管理、引渡し |
| 実教材でどう試すか | [実教材テスト手順](../user-material-test.md) | 実行例、比較、結果の記録用テンプレート |
| 品質をどう比較するか | [比較評価手順](../note-pipeline-evaluation.md) | 期待事項、評価の方法、実モデルの未評価項目 |
| 目指す書式を見たい | [授業ノートの見本](../note-example.md) | 架空の内容を使った期待する見た目 |
| 情報保持の具体例を見たい | [情報保持の見本](../note-fidelity-example.md) | 架空原文、期待応答、手順・例・不確実性の照合基準 |

## docs外の参照先

| 場所 | 役割と注意 |
| --- | --- |
| [README](../../README.md) | 導入・基本的な実行方法。この整理では編集対象外 |
| `AGENTS.md` | エージェント向けの作業ルール。ローカルのファイルはGit管理外 |
| `.codex/GEMINI_POLICY.md` | 無料枠限定のGemini実行許可と停止条件。ローカル設定でありGit管理外 |
| [prompts/article.md](../../prompts/article.md) | 外部化された記事化の文章方針。実際の送信方法は仕様・コードで確認する |
| [src](../../src) | 実装。本文の構造検証、API制御、保存処理の確認先 |
| [tests](../../tests) | オフライン検証。fixtureは架空素材であり実教材ではない |
| `learning_texts/` | ローカルの教材・原文・生成結果・レビュー。Git管理外で、本文を開発文書へ転記しない |
| `$review-lecture-notes` | 原文との照合・品質判定を行うユーザー共通Skill。標準配置は`~/.codex/skills/review-lecture-notes/SKILL.md`。`CODEX_HOME`指定環境では導入先を確認する |

ローカル設定やSkillは、このリポジトリを取得しただけでは揃わない。利用できない参照先があれば、その環境に適用されるルールを確認する。文書に書かれた参照先から、外部送信や有料API利用の権限を推測しない。

## 更新先を選ぶ

- 新しい動作を決める：要件・受入基準 → 仕様 → 設計・タスクの順に更新する。
- テストや実行で結果が出た：検証記録へ条件・結果・限界を記す。教材由来の詳細は教材管理場所に残す。
- 未解決の問題が見つかった：未解決問題へ事実と仮説・次の検証を整理し、タスクと対応付ける。
- 作業手順の案内を変える：開発の進め方や該当する手順書を更新し、規則の本文は管理元を参照する。
- ファイルを追加・移動する：この案内と相対リンクを確認する。既存文書の移動時にはREADME・AGENTS.md・テスト内の参照も調べ、編集対象外のファイルを無断で変更しない。

過去の検証記録には、その時点の仕様や未評価事項が残る。記録の日付と対象コミットを確認し、過去の成功や未実装という記述を現在の状態へ無条件に当てはめない。
