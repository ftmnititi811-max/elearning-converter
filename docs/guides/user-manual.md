## 導入

Windows 11、Python 3.11以降を基準とします。FFmpegとffprobeは別途導入し、PATHへ登録してください。

```powershell
py --version
ffmpeg -version
ffprobe -version
```

リポジトリを取得し、プロジェクト直下で実行します。取得済みなら`git clone`と`cd`を省き、既存のプロジェクトフォルダで続けてください。

```powershell
git clone https://github.com/ftmnititi811-max/elearning-converter.git
cd elearning-converter
py -m venv .venv
.\.venv\Scripts\Activate.ps1
python -m pip install -e .
elconv --help
```

既定の音声認識はWhisper `small`、CPU/int8、日本語です。初回は認識モデルをダウンロードする場合があり、その後の音声認識はローカルで行います。

PowerShellで仮想環境を有効化できない場合は、実行ファイルを直接指定できます。

```powershell
.\.venv\Scripts\python.exe -m pip install -e .
.\.venv\Scripts\python.exe -m elearning_converter --help
```

以後の例の`elconv`は、同じ仮想環境の`python -m elearning_converter`でも実行できます。現状はソースと一緒に使うeditable installが対象で、wheelだけの配布には対応していません。

## APIキーの設定

Geminiを使う場合だけ必要です。読み込みの優先順位は環境変数`GEMINI_API_KEY`、次にプロジェクト直下の`.env`です。

`.env`を使う場合は、[.env.example](../../.env.example)を参考に次の形式で作成します。既にある`.env`を例で上書きしないでください。

```dotenv
GEMINI_API_KEY=your_gemini_api_key_here
```

環境変数を使う場合は、実行するPowerShellセッションで設定します。

```powershell
$env:GEMINI_API_KEY = "your_gemini_api_key_here"
```

上記は記入形式の例です。実際のキーはGit管理、ログ、スクリーンショット、共有するコマンド履歴へ残さないでください。`--no-article`ではキーを読みません。

## モードの選び方

| 用途 | 指定 | APIへ送るもの | 主な出力 |
| --- | --- | --- | --- |
| 文字起こしだけ作る | `--no-article` | 送信なし | 時刻付き原文 |
| 基本のノート生成 | 品質オプションなし | 文字起こし | ノートと原文 |
| 原文と生成ノートを照合する | `--quality-check` | 原文・生成ノート・重要事項・指摘 | ノート・原文・品質レポート |
| 台帳と章構成を経由する改善中の方式 | `--note-pipeline` | 原文・台帳・章構成・本文・指摘 | ノート・原文・品質レポート |

出力はMP4入力が正常に完了した場合です。`--from-transcript`を使う場合は音声処理と原文の保存を省略します。品質確認の不合格などでは記事を保存しません。

`--quality-check`と`--note-pipeline`は併用できません。いずれも`--no-article`とは併用不可です。品質確認の「合格」はモデルの判定であり、正しさや欠落の完全な検出を保証しません。

## 基本操作

入力MP4と出力先を指定します。日本語・空白入りパスは引用符で囲んでください。

```powershell
# APIなしで原文だけを作成
elconv "C:\講義 資料\授業.mp4" --no-article --output-dir "C:\復習 ノート"

# 通常のノート生成
elconv "C:\講義 資料\授業.mp4" --output-dir "C:\復習 ノート"
```

出力先を省略すると入力と同じフォルダへ保存します。元MP4は変更しません。字幕・映像・スライド解析、話者分離、GUI、一括処理には対応していません。

## 既存の文字起こしを使う

```powershell
elconv "C:\教材\授業.transcript.md" --from-transcript --output-dir "C:\教材\再生成"
```

音声抽出・Whisperを省き、記事のみを生成します。`.transcript.failed.md`も利用できます。入力原文を変更せず、複製や救済原文も保存しません。`--language`と`--whisper-model`は使用せず、`--no-article`とは併用できません。

入力はelconv形式のUTF-8（BOM可）です。タイトル・既定注記・空行と、`[HH:MM:SS] 本文`の行を受け付けます。時刻は非減少（同時刻可）、分・秒は00〜59、本文は非空である必要があります。未知の行、逆順時刻、読取不能、空結果はAPI前に拒否します。入力と同一実体への出力は`--overwrite`指定時も拒否します。

## 独立照合を行う

```powershell
elconv "C:\教材\授業.transcript.md" --from-transcript --quality-check --output-dir "C:\教材\品質確認"
```

MP4入力にも指定できます。同じモデルへの独立リクエストで生成と原文照合を行い、指摘があれば本文を1回修正して再照合します。

- 通常2工程、修正時は最大4工程／分割。通信再試行は別に数えます。
- 最終照合でmajorが残る場合は全記事を保存せず、既存記事を保持します。minorのみなら保存します。
- 形式不正は修正依頼で救済せず失敗します。
- 品質レポートにはモデル、工程数、実試行数、初回・再照合の指摘を記録します。

原文の誤認識、不明な式・変数名などは音声や講義資料で確認してください。適切に留保した箇所への誤指摘もあり得るため、モデルの指摘内容を人手で確認します。

## 台帳方式を使う

**改善中の方式です。2026-11-04の実教材3本の評価では、応答形式不正や必須情報の未掲載で完成記事に至りませんでした。** [未解決問題](../issues/known-issues.md)を確認してから評価用途で利用してください。

```powershell
elconv "C:\教材\授業.transcript.md" --from-transcript --note-pipeline --max-api-calls 40 --output-dir "C:\教材\台帳方式"
```

MP4入力にも使えます。処理は次の順です。

1. 原文IDを付与して分割し、各窓の情報台帳を抽出・原文照合する
2. 全台帳から講義順の章構成を計画する
3. 章ごとの根拠原文を集め、段落・箇条書き・手順・表・コードを生成する
4. 対象情報と本文を照合し、指摘時のみ1回修正・再照合する
5. 隣接する本文間の境界を原文と照合する

IDの存在・重複・原文網羅、必須情報の本文対応、根拠集合、章の順序、表の列数等をローカルでも検査します。原文の意味を正しく残せたかはID検査だけでは保証できません。

抽出は約12,000文字を上限に、話題転換・文末・開始時刻間隔を境界候補にします。本文生成単位は章と根拠原文量で別途決まります。章計画資料のJSONが暫定120,000文字を超える場合は切り捨てず失敗します。

台帳・本文・境界の重大な問題、形式・通信エラー、工程上限、レポート保存失敗では記事を確定しません。レポートには原文ID・時刻・文字範囲、台帳・除外理由、章構成、ブロック対応、照合履歴、工程別の時間・使用量を記録します。教材由来の内容を含むため教材と同じ扱いで管理してください。

## オプション一覧

```powershell
elconv --help
```

| オプション | 既定・動作 |
| --- | --- |
| `INPUT` | MP4。`--from-transcript`時は対応する原文Markdown |
| `--output-dir DIR` | 入力と同じフォルダ |
| `--language LANGUAGE` | `ja`。MP4の認識言語 |
| `--whisper-model MODEL` | `small`。CPU/int8で認識 |
| `--article-model MODEL` | `gemini-3.5-flash-lite`。Geminiモデルを明示指定できる |
| `--no-article` | APIを使わず原文だけを保存 |
| `--from-transcript` | 原文を読み込み、記事生成のみ実行 |
| `--quality-check` | 原文との独立照合と限定修正 |
| `--note-pipeline` | 台帳・章構成・構造化本文・境界照合 |
| `--max-api-calls N` | 台帳方式専用の正整数。既定100工程、通信再試行別 |
| `--overwrite` | 既存出力の置換を許可 |

`--max-api-calls`を台帳方式以外に指定すると設定エラーです。モデル名・分割長等は暫定値で、品質・時間・使用量を測って設定を判断してください。

## 出力と上書き

| ファイル | 内容・作成条件 |
| --- | --- |
| `<stem>.md` | 正常に確定した復習用ノート |
| `<stem>.transcript.md` | MP4から作成した時刻付き原文。`--no-article`でも保存 |
| `<stem>.transcript.failed.md` | MP4経路で記事化に失敗した場合、可能なら保存する救済原文 |
| `<stem>.quality.md` | 品質確認・台帳方式のレポート。記事が保存されなくても作成される場合あり |

文字コードはUTF-8です。原文入力時は`.transcript.md`または`.transcript.failed.md`を名前から除いた`<stem>.md`へ保存します。既存のノート・原文・レポート・救済原文の置換には`--overwrite`が必要です。比較には出力先を分けると過去の結果を保持できます。

```powershell
elconv "C:\教材\授業.transcript.md" --from-transcript --overwrite --output-dir "C:\教材\再生成"
```

記事化の失敗では不完全記事を最終名にせず、既存記事を保持します。ファイルは一時ファイルから置換しますが、複数ファイルを完全に同時確定するものではありません。品質レポートは記事確定前に保存されるため、「合格」だけでは保存成功を断定せず、CLIの終了結果と記事を確認してください。

終了コードは成功`0`、入力・設定不備`2`、処理失敗`1`です。PowerShellでは実行直後の`$LASTEXITCODE`で確認できます。

## 送信範囲とAPI利用量

MP4/WAVは送信しません。教材の加工・テキストの外部送信・共有が許可されているか確認し、個人情報や機密情報を含む場合は送信可否を確認してください。出力は復習用下書きとして原音声と照合します。

| 方式 | API工程数（通信再試行を除く） | 統合・追加処理 |
| --- | --- | --- |
| 通常 | 原文の分割数 | 分割記事をローカルで結合。全体の再生成APIは呼ばない |
| 品質確認 | 通常2、修正時最大4／分割 | 生成・照合、必要時の修正・再照合 |
| 台帳方式 | 通常`2W+1+2J+max(J-1,0)`、修正時最大`2W+1+4J+max(J-1,0)` | 全台帳の章構成、J単位の本文生成、境界照合 |

Wは抽出窓数、Jは本文生成単位数です。台帳方式でW=J=1なら通常5工程、修正時7工程です。**`--max-api-calls`は工程数の制限であり、トークン量・料金の上限ではありません。** CLIは無料枠の課金状態や残量も自動判定しません。

通常・旧品質方式は408/429/5xxと通信障害をアプリ側で最大3試行します。これらの方式の試行数記録はアプリ側の呼出しを数え、SDK内の再試行を含む実通信回数はSDK設定にも依存します。台帳方式は429で即停止し、SDK内部の再試行も禁止します。その他の一時障害だけアプリ側で最大3試行します。形式不正による自動再送信は行いません。

利用前に[Gemini公式料金表](https://ai.google.dev/gemini-api/docs/pricing)、[モデル仕様](https://ai.google.dev/gemini-api/docs/models/gemini-3.5-flash-lite)、自分のプロジェクトの利用状況を確認してください。ここには料金や無料枠の上限値を固定しません。台帳方式のレポートにあるトークン数は取得分の集計です。不明試行があれば完全な請求量とは扱わず、prompt/candidates/thoughts/cachedを単純に合算しないでください。

エージェントに実行を依頼する場合は、適用されるAGENTS.mdとローカルの`.codex/GEMINI_POLICY.md`にも従います。これらのローカル設定はGit管理外です。

## 書き方の調整

[prompts/article.md](../../prompts/article.md)をUTF-8で編集すると次の記事化から反映します。プロジェクト直下を参照するため、起動時の作業ディレクトリには依存しません。記事化開始時に1回読み、各対象へ同じ文章方針を使います。

通常・旧品質方式の`body/checks`、`heading/text/timestamp`の指示と末尾の「文字起こし:」を維持してください。品質方式は応答を`article/facts`へ包み、台帳方式は後から`blocks/checks`の構造指示を付けて優先します。文章方針の調整と応答契約の変更を区別し、JSON構造の変更には実装と仕様の更新が必要です。

欠落・読取不能・不正なUTF-8・空白のみならAPIを呼ばず失敗します。MP4経路では原文を救済します。`--no-article`ではプロンプトは不要です。

## トラブル対応

| 症状・表示 | 確認すること |
| --- | --- |
| FFmpegまたはffprobeが見つからない | 両コマンドをPATHに登録し、`-version`で確認 |
| APIキーが未設定 | プロジェクト直下の`.env`または実行するPowerShellの環境変数を確認 |
| 文字起こし結果が空 | 入力に聞き取れる音声があるか確認 |
| 既存出力がある | 別の出力先を指定。置換を意図する場合のみ`--overwrite` |
| 原文Markdownの形式が不正 | 時刻の順序・分秒・本文、未知の行、UTF-8を確認 |
| `finish_reason=MAX_TOKENS` | APIの生成打切り。不完全応答は採用されない |
| `block_reason`・`finish_reason=SAFETY`等 | API側の入力ブロック・生成停止 |
| 空応答・JSON構文不正 | 分割番号と固定理由、構文の行・列を記録 |
| 形式不正・未知ID・必須情報未掲載 | 台帳方式では既知の問題あり。理由を確認し、同じ失敗を無計画に再実行しない |
| HTTP 429 | 制限や利用量を確認。台帳方式は追加送信せず停止 |
| API工程上限に到達 | レポートで進行状況を確認。単に上限を増やす前に利用枠・必要工程を確認 |
| レポート保存失敗 | 出力先の権限・既存ファイルを確認。記事は確定されない |

キー・本文・APIの生エラーはCLIログに出しません。生応答も保存しないため、汎用エラーだけの過去記録から具体的な不正値を確定できない場合があります。原文入力で失敗した場合は入力原文が保持されています。MP4経路では救済原文の有無も確認してください。
